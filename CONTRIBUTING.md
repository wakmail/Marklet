# Contributing

Marklet is developed in a private repository by one person, so it is not open to outside pull requests at the
moment. That may change later. In the meantime there are still useful ways to help.

## What helps most right now

* **Bug reports.** Steps to reproduce, your Marklet and macOS versions, and the smallest document that triggers it.
* **Feature ideas.** Tell us what you are trying to write and where Marklet gets in the way. The problem is more
  useful to us than a proposed solution.
* **Security reports.** Please follow SECURITY.md and keep them private.

## If you want to contribute code

Get in touch first at hello@getmarklet.com and say what you would like to work on. That way nobody spends an
evening on something already half written, or on something that will not fit where the app is going.

## House rules, if you do end up writing code here

* Branch before starting anything. Never commit straight onto main.
* `swift test` must pass before a change is considered done.
* Keep each commit to one concern, and write commit messages in plain words.
* No dashes anywhere in prose, documentation, or user facing strings. Not em dashes, not en dashes, not hyphens.
  Rephrase instead. Code and identifiers are exempt.
* Update Docs/CHANGELOG.md when behaviour changes.
* Match the surrounding code: same naming, same comment density, same idioms.

## Code of conduct

Everyone taking part is expected to follow CODE_OF_CONDUCT.md.
